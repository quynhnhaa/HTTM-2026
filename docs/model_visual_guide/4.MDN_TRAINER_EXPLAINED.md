# Đọc hiểu `base_mdn/mdn.py`

## Vai trò của file

`train.py` chuẩn bị model, loss, optimizer và dữ liệu. `mdn.py` chứa vòng training thật:

```text
epoch
-> lấy random 50% train data
-> chia batch
-> forward
-> NLL
-> backward
-> Adam update
-> validation
-> history/checkpoint
-> full evaluation định kỳ
```

Một epoch hoàn chỉnh:

```text
model.train()
├── 24 train batches
│   ├── zero_grad
│   ├── forward
│   ├── NLL
│   ├── backward
│   └── optimizer.step
├── mean train batch losses
├── scheduler.step()
├── model.eval()
├── 3 validation batches trong no_grad
├── mean validation batch losses
├── log/history/checkpoint
└── full metrics nếu tới lịch
```

## 1. Import

```python
import os
import torch
import numpy as np
import time

from eval import MDN_Forecaster
from statistics import mean
from vis import plot_train_loss
from termcolor import colored
```

- `os`: ghép checkpoint paths;
- `torch`: tensor, `no_grad`, GPU memory;
- `numpy`: dynamic horizon và kiểm tra finite;
- `time`: đo duration mỗi epoch;
- `MDN_Forecaster`: chạy full evaluation;
- `mean`: trung bình batch losses;
- `plot_train_loss`: cập nhật biểu đồ NLL;
- `colored`: màu terminal.

## 2. Class `MDN_Trainer`

```python
class MDN_Trainer:
```

Trainer không tự tạo model, loss hoặc Adam. Nó nhận các object đã được `train.py` tạo và điều phối quá trình sử dụng chúng.

## 3. Constructor

```python
def __init__(
    self,
    cfg,
    model,
    loss_fn,
    optimizer,
    scheduler,
    epoch,
    loss_hist,
    logger,
    device='cpu',
    tracker=None
):
```

Các dependency:

```text
cfg       -> config đã resolve
model     -> LSTM + Linear
loss_fn   -> NLL_MDN_loss với K=3
optimizer -> Adam
scheduler -> LinearLR
epoch     -> epoch bắt đầu
loss_hist -> history cũ hoặc rỗng
logger    -> training logger
device    -> CPU/GPU
tracker   -> ExperimentTracker
```

## 4. Lưu các object chính

```python
self.cfg = cfg
self.model = model.to(device)
self.loss_fn = loss_fn
self.optimizer = optimizer
self.scheduler = scheduler
self.device = device
self.epoch = epoch
self.history = loss_hist
```

`model.to(device)` bảo đảm model ở cùng device với batch input. Train mới bắt đầu từ epoch 1; resume từ checkpoint epoch 100 bắt đầu ở epoch 101.

## 5. Khôi phục loss lists

```python
self.train_loss_per_epoch_list = (
    [row['train_nll'] for row in loss_hist]
    if loss_hist and isinstance(loss_hist[0], dict)
    else list(loss_hist)
)
```

Code hỗ trợ:

- history mới: list các dictionary có `train_nll`;
- checkpoint cũ: list các scalar train losses.

Validation:

```python
self.validation_loss_per_epoch_list = (
    [row['validation_nll'] for row in loss_hist]
    if loss_hist and isinstance(loss_hist[0], dict)
    else []
)
```

Checkpoint cũ không có validation history thì dùng list rỗng.

## 6. Model parameters trong trainer

```python
self.dt = cfg.model_params['delta_t']
self.num_gaussians = cfg.model_params['num_gaussians']
self.forecast_horizon = cfg.model_params['forecast_horizon']
```

Baseline:

```text
dt = 0,1 s
num_gaussians = 3
forecast_horizon = 48
```

## 7. Training parameters

```python
self.dynamic_input_horizon = cfg.train_params['dynamic_input_horizon']
self.resume_training = cfg.train_params['resume_training']
self.train_batch_size = cfg.train_params['batch_size']
self.train_epochs = cfg.train_params['train_epochs']
self.eval_epoch_step = cfg.train_params['eval_epoch_step']
self.min_dynamic_input_horizon = cfg.train_params['min_dynamic_input_horizon']
```

Baseline:

```text
dynamic_input_horizon = False
batch_size = 4096
train_epochs = 2500
eval_epoch_step = 2500
min_dynamic_input_horizon = 32
```

## 8. Evaluation/plot parameters

```python
self.confidence_levels = cfg.test_params['confidence_levels']
self.mesh_range_x = cfg.test_params['mesh_range_x']
self.mesh_range_y = cfg.test_params['mesh_range_y']
self.mesh_resolution = cfg.test_params['mesh_resolution']
self.num_samples = cfg.test_params['num_samples']
```

Các giá trị này không tham gia NLL/backward. Chúng chỉ phục vụ full evaluation và visualization.

```text
confidence levels = 95%, 68%
mesh = [-18,18] x [-18,18]
resolution = 0,1
MC samples = 1000
```

# Hàm `save()`

## 9. Legacy checkpoint dictionary

```python
checkpoint = {
    'epoch': epoch,
    'model': self.model.state_dict(),
    'optimizer': self.optimizer.state_dict(),
    'scheduler': self.scheduler.state_dict(),
    'loss': self.train_loss_per_epoch_list,
    'train_history': self.history
}
```

Nó lưu model weights, Adam state, scheduler state, epoch và loss/history. Đây là cơ chế save legacy, tách biệt với checkpoint giàu metadata của `ExperimentTracker`.

## 10. Final và periodic legacy files

```python
if final:
    torch.save(checkpoint, 'model_final.pt')
else:
    torch.save(
        checkpoint,
        f'{config_name}_{epoch:04d}.pt'
    )
```

Ví dụ periodic legacy file:

```text
default_peds_imptc_0250.pt
```

## 11. Khi distribution build báo divergence

```python
if diverged:
    torch.save(checkpoint, 'model_final.pt')
    ...
    return
```

Trainer lưu trạng thái gần nhất rồi dừng. Cờ này đến từ `NLL_MDN_loss()` khi dựng GMM phát sinh exception. Vì loss dùng bare `except`, một lỗi shape/lập trình cũng có thể được báo chung là divergence.

# Hàm `train()`

## 12. Khởi tạo `final_epoch`

```python
final_epoch = self.epoch
```

Mỗi lần bước vào epoch:

```python
final_epoch += 1
```

Cuối hàm trả:

```python
final_epoch - 1
```

Run đầy đủ từ 1 đến 2500 sẽ trả 2500. Cách viết này hoạt động nhưng khó đọc hơn việc gán trực tiếp `final_epoch = epoch`.

## 13. Vòng epoch

```python
for epoch in range(
    self.epoch,
    self.train_epochs + 1
):
```

Train mới:

```text
1,2,...,2500
```

Resume từ epoch 101:

```text
101,102,...,2500
```

## 14. Bắt đầu epoch

```python
st = time.time()
train_loss_list = []
final_epoch += 1
self.model.train()
current_lr = self.optimizer.param_groups[0]['lr']
```

- `st`: thời gian bắt đầu;
- `train_loss_list`: scalar loss của từng batch;
- `model.train()`: bật train mode;
- `current_lr`: learning rate dùng cho epoch hiện tại trước scheduler step.

# Train data và batch loop

## 15. Lấy random 50% train data

```python
train_data_X, train_data_y = data_loader.get_train_data()
```

DataLoader thực hiện:

```text
shuffle full train arrays
-> chọn random 50%
-> trả X,y
```

Shape:

```text
train_data_X [94797,32,4]
train_data_y [94797,48,2]
```

## 16. Chia batch thủ công

```python
for iteration in range(
    0,
    len(train_data_X),
    self.train_batch_size
):
```

Với 94.797 sample và batch size 4.096:

```text
24 batch/epoch
```

Cụ thể:

```text
23 batch x 4096 = 94208 sample
1 batch cuối     = 589 sample
```

## 17. NumPy batch thành float32 tensor

```python
inputs = torch.tensor(
    train_data_X[iteration:iteration+batch_size],
    dtype=torch.float32
)
targets = torch.tensor(
    train_data_y[iteration:iteration+batch_size],
    dtype=torch.float32
)
```

Batch đầy:

```text
inputs  [4096,32,4]
targets [4096,48,2]
```

Raw pickle là `float64`; model chạy với `float32`.

## 18. Dynamic input horizon

```python
if self.dynamic_input_horizon:
    n = np.random.choice(
        range(
            self.min_dynamic_input_horizon,
            inputs.size()[-2],
            1
        )
    )
    inputs = inputs[:, n:, :]
```

Baseline đang tắt nhánh này.

Nếu `n=10` và input length 32:

```text
inputs[:,10:,:]
-> giữ 22 timestep cuối
```

`n` là start index, không phải số timestep được giữ.

Với config hiện tại nếu bật:

```text
range(32,32,1)
```

là range rỗng và `np.random.choice()` sẽ lỗi. Không nên bật cờ này mà không xem lại logic/config.

## 19. Chuyển batch sang device

```python
inputs = inputs.to(self.device)
targets = targets.to(self.device)
```

Model, inputs và targets phải cùng CPU/GPU.

## 20. Xóa gradient cũ

```python
self.optimizer.zero_grad()
```

PyTorch cộng dồn gradient theo mặc định. Nếu không zero, gradient batch mới sẽ cộng với batch trước.

## 21. Forward

```python
outputs = self.model(inputs)
```

Shape:

```text
inputs  [B,32,4]
outputs [B,48,18]
```

## 22. NLL loss

```python
loss, diverged = self.loss_fn(outputs, targets)
```

Loss thực hiện:

```text
raw output
-> 48 GMM
-> log density tại ground truth
-> negative mean trên B x 48
-> một scalar
```

## 23. Nếu loss báo divergence

```python
if diverged:
    self.save(epoch, diverged=True, final=False)
    return final_epoch - 1, self.train_loss_per_epoch_list
```

Training lưu checkpoint và dừng ngay. Nếu xảy ra giữa epoch, epoch đó chưa được thêm vào history.

## 24. Backward và Adam update

```python
loss.backward()
self.optimizer.step()
```

`backward()` tính gradient nhưng chưa thay đổi weights. `optimizer.step()` dùng gradient để cập nhật LSTM và Linear một lần.

Mỗi batch:

```text
1 backward
1 optimizer update
```

Với config hiện tại:

```text
24 updates/epoch
```

Loop hiện không có gradient clipping và không có automatic mixed precision.

## 25. Lưu batch loss

```python
train_loss_list.append(loss.item())
```

`loss.item()` chuyển scalar tensor thành Python number. Sau train loop, list chứa khoảng 24 batch losses.

## 26. Train NLL của epoch

```python
train_loss = mean(train_loss_list)
```

Đây là trung bình đều giữa 24 batch means:

```text
(L_1 + ... + L_24) / 24
```

Batch cuối chỉ có 589 sample nhưng vẫn có trọng số bằng một batch 4096 sample. Vì vậy epoch NLL hiện không phải sample-weighted mean chính xác trên toàn bộ 94.797 sample.

## 27. Scheduler step

```python
self.scheduler.step()
```

Được gọi sau train batches và trước validation. Scheduler không thay đổi weights, chỉ giảm learning rate dùng cho epoch tiếp theo.

`current_lr` đã được đọc trước scheduler step, nên history/log ghi learning rate thực sự dùng trong epoch vừa train.

# Validation loop

## 28. Eval mode

```python
self.model.eval()
val_loss_list = []
```

Model hiện không có dropout/batch normalization, nhưng đây vẫn là quy trình PyTorch chuẩn.

## 29. Lấy random 50% validation data

```python
eval_data_X, eval_data_y, _, _, _ = data_loader.get_eval_data()
```

Trainer bỏ `reference_position`, `rotation_angle`, `source` vì validation NLL chỉ cần `X,y`.

Shape:

```text
eval_data_X [9574,32,4]
eval_data_y [9574,48,2]
```

Subset được chọn lại ngẫu nhiên mỗi lần gọi.

## 30. Tắt gradient

```python
with torch.no_grad():
```

Validation:

- không xây computation graph;
- không gọi backward;
- không cập nhật model;
- dùng ít memory hơn.

## 31. Validation batches

Validation dùng `train_batch_size=4096`, không dùng test batch size 128.

```text
ceil(9574/4096) = 3 batch
```

Hai batch đầu có 4096 sample, batch cuối có 1382 sample.

## 32. Validation forward và loss

```python
outputs = self.model(inputs)
loss, diverged = self.loss_fn(outputs, targets)
```

Validation dùng đúng cùng model, GMM decoder và NLL formula với training, nhưng không có:

```text
loss.backward()
optimizer.step()
```

## 33. Validation NLL của epoch

```python
eval_loss = mean(val_loss_list)
```

Ba batch losses được weighting bằng nhau, dù batch cuối nhỏ hơn. Vì vậy validation NLL cũng không phải sample-weighted mean chính xác.

Nó còn có thể dao động do:

```text
model thay đổi
+
random validation subset thay đổi
```

# Kết thúc một epoch

## 34. Lưu loss lists và vẽ biểu đồ

```python
self.train_loss_per_epoch_list.append(train_loss)
self.validation_loss_per_epoch_list.append(eval_loss)
plot_train_loss(...)
```

Biểu đồ train/validation NLL được cập nhật mỗi epoch trong `evaluation_path`.

## 35. Duration và ETA

```python
duration = round(time.time() - st, 2)
eta = round(
    duration * (train_epochs - epoch) / 3600,
    2
)
```

ETA là duration epoch hiện tại nhân số epoch còn lại. Duration được tính trước full evaluation phía dưới, nên ETA có thể đánh giá thấp thời gian thực ở các metric epochs.

## 36. Epoch history row

```python
row = {
    'run_id': ...,
    'epoch': epoch,
    'train_nll': float(train_loss),
    'validation_nll': float(eval_loss),
    'learning_rate': float(current_lr),
    'duration_seconds': float(duration),
    'train_sample_count': len(train_data_X),
    'validation_sample_count': len(eval_data_X),
    'gpu_peak_memory_bytes': ...,
    'finite': ...,
}
```

Baseline ghi:

```text
train_sample_count = 94797
validation_sample_count = 9574
```

`finite` kiểm tra train/eval NLL không phải NaN hoặc infinity. Tại đây cờ chỉ được ghi vào history, không tự dừng run.

`torch.cuda.max_memory_allocated()` không được reset mỗi epoch trong file này, nên đây là peak tích lũy của process/device, không nhất thiết peak riêng epoch hiện tại.

## 37. Thêm row vào history

```python
self.history.append(row)
```

History được dùng cho CSV, checkpoints, resume và phân tích sau training.

# Checkpoint scheduling

## 38. Best checkpoint

```python
is_best = self.tracker.update_best(
    epoch,
    eval_loss,
    self.model,
    self.optimizer,
    self.scheduler,
    self.history
)
```

Nếu validation NLL thấp hơn best trước đó, tracker lưu best checkpoint.

Best được chọn theo:

```text
validation NLL
```

không phải ADE, FDE, reliability hay sharpness.

## 39. Periodic checkpoints

```python
if self.tracker.should_checkpoint(epoch):
    self.tracker.save_checkpoint(
        f'epoch_{epoch:04d}',
        ...
    )
```

Config:

```json
"checkpoint_epochs": [1,5,10],
"checkpoint_every": 100
```

Lịch:

```text
1, 5, 10, 100, 200, ..., 2500
```

Các checkpoint chỉ định/định kỳ có thể capture fixed-sample predictions.

## 40. Last checkpoint

```python
if epoch % save_last_every == 0:
    self.tracker.save_checkpoint(
        'last',
        ...,
        capture_predictions=False
    )
```

`save_last_every=1`, nên `last` được cập nhật mỗi epoch. Nó chủ yếu phục vụ resume. Không capture predictions mỗi epoch để giảm artifact volume.

## 41. Hoàn thiện và ghi epoch row

```python
row.update({
    'is_best': is_best,
    'checkpoint_saved': checkpoint_saved,
    'full_metrics_evaluated':
        self.tracker.should_evaluate_metrics(epoch),
    'timestamp_utc': ...
})
self.tracker.log_epoch(row)
```

`row` đã được append vào history dưới dạng cùng dictionary object, nên `row.update()` cũng cập nhật item tương ứng trong history.

Biến local `full_metrics_evaluated=False` được khai báo trước đó nhưng không được dùng; code gọi `should_evaluate_metrics()` trực tiếp.

# Full evaluation

## 42. Quyết định metric epoch

```python
run_full_evaluation = (
    self.tracker.should_evaluate_metrics(epoch)
    if self.tracker
    else (
        epoch % self.eval_epoch_step == 0
        and epoch != 0
    )
)
```

Khi tracker tồn tại, config `metric_every=250` được dùng:

```text
250,500,750,...,2500
```

Fallback `eval_epoch_step=2500` chỉ dùng khi không có tracker.

## 43. Full evaluation khác validation NLL

Validation mỗi epoch chỉ tính:

```text
forward + NLL
```

Full evaluation còn tính:

- sampled trajectories;
- minADE20;
- minFDE20;
- reliability;
- sharpness 68%;
- sharpness 95%;
- ASAEE;
- optional example plots.

Các metric này không gọi backward và không cập nhật model.

## 44. Legacy save trước full evaluation

```python
self.save(
    epoch=epoch,
    diverged=False,
    final=False
)
```

Tạo legacy checkpoint `<config_name>_<epoch>.pt`.

## 45. Tạo eval forecaster

```python
eval_forecaster = MDN_Forecaster(
    cfg=self.cfg,
    model=self.model,
    data_loader=data_loader,
    type='eval',
    device=self.device,
    logger=self.logger
)
```

`type='eval'` nghĩa là dùng validation split, không dùng test split.

Forecaster gọi lại `get_eval_data()`, nên có thể chọn một random 50% subset mới, khác subset vừa dùng tính validation NLL.

## 46. Chạy và lưu metrics

```python
metric_values = eval_forecaster.evaluate(epoch=epoch)
self.tracker.save_metrics(epoch, metric_values)
```

Reliability, S68 và S95 xuất hiện ở bước này, không nằm trong batch loss.

## 47. Optional plots

```python
if self.plot_examples or self.plot_map_examples:
    eval_forecaster.save_examples(...)
```

Baseline đang đặt hai cờ là `False`, nên không tạo hàng loạt example plots theo cơ chế cũ trong training.

# Kết thúc training

## 48. Thông báo epoch và return

```python
return (
    final_epoch - 1,
    self.history
    if self.tracker
    else self.train_loss_per_epoch_list
)
```

Với tracker, trả structured history. Không có tracker thì chỉ trả train-loss list.

`train.py` dùng `final_epoch` và history để lưu final checkpoints.

## 49. Bản đồ một batch

```text
NumPy X,y slice
-> float32 tensors
-> move to CPU/GPU
-> optimizer.zero_grad()
-> outputs = model(inputs)
-> loss = NLL(outputs,targets)
-> loss.backward()
-> optimizer.step()
-> append loss.item()
```

## 50. Bản đồ một epoch

```text
Bắt đầu epoch
|
|-- model.train()
|-- get_train_data(): shuffle + random 50%
|-- 24 train batches
|-- mean train batch losses
|-- scheduler.step()
|
|-- model.eval()
|-- get_eval_data(): random 50%
|-- 3 validation batches trong no_grad
|-- mean validation batch losses
|
|-- cập nhật loss plot
|-- ghi history
|-- update best
|-- periodic checkpoint nếu tới lịch
|-- update last
|
`-- nếu metric epoch
    |-- MDN_Forecaster
    |-- ADE/FDE
    |-- reliability
    |-- S68/S95
    `-- ASAEE
```

## 51. Các điểm cần nhớ

1. Mỗi train batch cập nhật model đúng một lần.
2. Baseline có khoảng 24 updates/epoch.
3. Validation không cập nhật model.
4. Scheduler step một lần mỗi epoch.
5. Train và validation chỉ dùng random 50% split mỗi epoch.
6. Epoch train/eval NLL là mean đều theo batch, không weighting theo batch size cuối.
7. Best checkpoint được chọn theo validation NLL.
8. `last` được cập nhật mỗi epoch.
9. Full metrics chạy khoảng mỗi 250 epoch.
10. Reliability và S68/S95 không tham gia backward.
11. Dynamic input horizon đang tắt; bật với config hiện tại sẽ gặp range rỗng.
12. Full evaluator có thể dùng eval subset khác validation NLL trong cùng epoch.

## Kết luận

`mdn.py` là trái tim của quá trình tối ưu:

```text
data subset
-> batches
-> forward GMM
-> NLL với ground truth
-> backward
-> Adam update
-> validation
-> checkpoint và metrics
```

File tiếp theo cần đọc là `base_mdn/utils/experiment.py`, nơi định nghĩa chính xác seed/RNG state, fixed samples, best/last/periodic/final checkpoints, history và resume artifacts.
