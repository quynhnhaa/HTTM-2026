# Shared-decoder MDN with LSTM hidden 64 (pre-declared, 2026-10-04)

Change relative to the first shared-decoder run (`sd_seed2024`, hidden 8): only `lstm_hidden_size` 8 -> 64. The shared MLP decoder (hidden 64, 4 Fourier frequencies), K = 3, loss, optimizer, schedule, preprocessing, metrics and seed 2024 are unchanged. One run, one value chosen in advance, no tuning.

Motivation (hypothesis, not proven): the hidden-8 shared-decoder run was worse than baseline K = 3 on validation (best NLL -1.006 vs -1.150) with a train-validation gap similar to the baseline (about 0.18 vs 0.19) and was still improving at epoch 2500, which suggests limited capacity. A wider encoder state gives the shared decoder more to work with. No direct evidence yet; more capacity may also increase overfitting.

Criteria (validation, same protocol and seed as baseline K = 3): NLL, Ravg, Rmin not worse than baseline K = 3 and S68 / S95 not worse; otherwise reported as a negative result. Single seed: small differences are not conclusions. The test split is evaluated exactly once for this configuration, at the user's request after the validation run finished (validation results were seen before that decision, the configuration was already fixed and was not changed); the baseline test numbers come from `results/ablations/imptc_num_gaussians/ablation.json` (reproduced exactly by the per-sample evaluation). No change after seeing the test result. Note this stacks two changes (shared decoder + wider encoder) relative to the baseline; it does not isolate the effect of the wider encoder alone.
